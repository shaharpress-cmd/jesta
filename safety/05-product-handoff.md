# מסירה למוצר — מסכים, שדות, MVP

מסמך מעשי לצוות/סוכן מוצר של ג'סטה.  
עקרון: כלים למשתמש + אוטומציה קלה. **לא** בונים מוקד גישור.

מיצוב קבוע ב־UI (כבר בקוד):
- `SAFETY` ב־`src/lib/categories.ts`
- `SafetyBanner` — `tip` | `chat` | `footer`

---

## 1. מה לבנות ב-MVP (חובה)

### 1.1 כפתור דיווח
| פריט | פירוט |
|------|--------|
| איפה | פרופיל משתמש, כרטיס עזרה, תפריט שיחה (⋯), הודעה בודדת (אופציונלי אם קל) |
| זרימה | לחיצה → בחירת סיבה → פרטים רשותיים (עד 500 תווים) → שליחה → מסך "קיבלנו" |
| סיבות | לפי הטבלה ב־`02-reports-queue.md` (`harassment`, `threats`, `spam`, `scam`, `impersonation`, `inappropriate`, `fake_profile`, `other`; `no_show_abuse` אפשר לדחות ל־MVP+) |
| אחרי שליחה | יצירת רשומת `reports` + הודעת אישור (תבנית מ־`03`) · **בלי** הבטחת זמן/תוצאה |

### 1.2 חסימת משתמש
| פריט | פירוט |
|------|--------|
| איפה | פרופיל + תפריט שיחה |
| התנהגות | מיידי: לא רואים כרטיסים אחד של השני (או מסתירים), לא שולחים הודעות, שיחה מסומנת כחסומה |
| UI | אישור קצר: "נחסם… אפשר גם לדווח" |
| ביטול חסימה | אפשר ב-MVP אם זול; אחרת MVP+ |

### 1.3 מיקומי טיפי בטיחות (קיים / להשלים)
| מקום | variant / טקסט | סטטוס |
|------|----------------|--------|
| פיד / לפני יצירת קשר | `tip` — מקום ציבורי | קיים `SafetyBanner` |
| מסך צ'אט (למעלה או מתחת לשדה) | `chat` — בלי כתובת מדויקת + דווח/חסום | קיים |
| פוטר פרופיל / אודות / תחתית מסכים מרכזיים | `footer` — מתווכת בלבד | קיים |
| מסך דיווח (לפני שליחה) | משפט אחד: האחריות על המפגש שלכם | לבנות |
| טולטיפ על "מאומת בסיסית" | לא בדיקת רקע / לא הבטחת בטיחות | לבנות |
| מסך בטיחות קצר (קישור מהגדרות) | כללי מפגש מ־`01` + מה שיווק לא טוען | MVP מומלץ / דף סטטי |

### 1.4 אימות בסיסי (תצוגה)
- תגית `מאומת בסיסית` / `מאומתת בסיסית` ליד שם — רק אם עבר תהליך בסיסי שמוגדר במוצר (למשל טלפון).
- **אסור** להציג "מאומת" סתם או "בטוח".

### 1.5 הגנות ספאם בסיסיות (שרת)
- מגבלת קצב הודעות לחשבון חדש.
- מגבלת קישורים בהודעה ראשונה.
- מונה דיווחים ייחודיים → דגל / הגבלה רכה (גם אם מסך אדמין עדיין פשוט).

## 2. שדות נתונים (הצעה)

### `reports`
| שדה | סוג | הערות |
|-----|-----|--------|
| id | uuid | |
| reporter_id | uuid | FK users |
| target_type | enum | `user` \| `jesta_card` \| `message` |
| target_id | uuid | |
| reason | enum | רשימת הסיבות |
| details | text nullable | מקס׳ ~500 |
| severity | enum | S0–S4; יכול להיקבע אוטומטית מ־reason |
| status | enum | `new` \| `auto_handled` \| `queued` \| `escalated` \| `closed` |
| auto_actions | jsonb | למשל `["hide_content","soft_limit"]` |
| created_at / resolved_at | timestamptz | |

### `blocks`
| שדה | סוג |
|-----|-----|
| blocker_id, blocked_id | uuid |
| created_at | timestamptz |
| unique(blocker_id, blocked_id) | |

### `user_restrictions` (MVP קל / MVP+)
| שדה | סוג | הערות |
|-----|-----|--------|
| user_id | uuid | |
| type | enum | `soft_limit` \| `temp_restrict` \| `banned` |
| until | timestamptz nullable | null = קבוע |
| reason_code | text | |
| created_by | `system` \| admin id | |

### הרחבות ל־`users` / פרופיל
- `verification_level`: `none` \| `basic`
- `is_banned` / או הסתמכות על `user_restrictions`
- מוני עזרה: `messages_sent_24h` (או rate limit בשרת בלי שדה)

## 3. זרימות מסך (בקצרה)

```
[פרופיל / צ'אט / כרטיס]
    ├─ חסום → אישור → blocks + empty state
    └─ דווח → סיבה → פרטים? → שליחה
            → "קיבלנו, נבדוק"
            → (אופציה) "לחסום גם?"

[צ'אט]
    └─ SafetyBanner chat קבוע בראש/ליד הקלט

[משתמש מוגבל]
    └─ פעולה אסורה → empty state מה־03

[אדמין — מינימום ב-MVP]
    └─ רשימת reports לפי status+severity
        → סימון closed / escalated
        → (ידני) temp_restrict / ban — רק שחר
```

**לא בונים ב-MVP:**
- צ'אט תמיכה דו־צדדי לגישור.
- כפתור "הזמן מתאם מפגש של ג'סטה".
- הבטחות SLA למשתמש.
- באדג' "משתמש בטוח".

## 4. MVP מול אחר כך

| נושא | MVP | אחר כך |
|------|-----|--------|
| דווח + חסום | ✅ | שיפור UX, דיווח על הודעה בודדת |
| SafetyBanner tip/chat/footer | ✅ (קיים) | טולטיפ אימות, דף בטיחות מלא |
| תור דיווחים | טבלה פשוטה / Supabase + סינון | דשבורד, שיוך, SLA פנימי |
| soft-limit / rate limit | ✅ שרת בסיסי | חוקים עשירים לפי קטגוריה |
| אזהרות למשתמש | תבניות ידניות / מייל | הודעות מערכת בתוך האפליקציה |
| הגבלה זמנית | ידני ע״י שחר או כלל פשוט | אוטומציה מלאה לפי N דיווחים |
| חסימה קבועה | ידני שחר בלבד | ערעור מובנה `[דורש עו״ד]` |
| מסנן מילות מפתח להונאה | רשימה קצרה בעברית | הרחבה + למידה |
| ביטול חסימה | אופציונלי | ✅ |
| התראות למדווח על "טופל" | אופציונלי גנרי | בלי פירוט פעולה |
| אימות מעבר לבסיסי | ❌ | רק אם מדיניות ברורה — בלי הבטחת "בטוח" |
| תשלומים | ❌ אין ב-MVP | כשיגיע: כללי הונאה נפרדים |

## 5. העתקה למוצר — מחרוזות מינימום לחיבור

הוסף/שמור ב־`SAFETY` או בקובץ מחרוזות:

```ts
// קיים
intermediary, publicPlace, noExactAddress, verifiedLabel, verifiedLabelF

// להוסיף (הצעה)
motto: "קהילה שעוזרת — באחריות"
reportReceived: "קיבלנו את הדיווח. נבדוק לפי הכללים שלנו."
blockedConfirm: "נחסם. הוא/היא לא יוכלו ליצור איתך קשר מג'סטה."
blockedEmpty: "אין אפשרות ליצור קשר עם המשתמש הזה."
verifiedTooltip: "אימות בסיסי של חשבון — לא בדיקת רקע ולא הבטחת בטיחות."
restrictEmpty: "החשבון מוגבל זמנית. בינתיים לא ניתן לבצע פעולה זו."
bannedEmpty: "החשבון נחסם לפי כללי הקהילה."
```

פירוט תבניות ארוכות: `03-warnings-blocks.md`.  
כללי מפגש מלאים: `01-meetup-rules.md`.

## 6. קריטריוני קבלה (מוצר)

- [ ] מכל פרופיל/צ'אט אפשר לדווח ולחסום ב־≤2 הקשות אחרי פתיחת התפריט.
- [ ] אחרי דיווח מוצג "קיבלנו…" בלי הבטחת תוצאה.
- [ ] באנרי tip/chat/footer עקביים ל־`SAFETY` ולא מבטיחים בטיחות.
- [ ] משתמש חסום לא יכול לשלוח הודעה לחוסם.
- [ ] תגית אימות לא משתמשת במילה "בטוח".
- [ ] אין מסך או זרימת "גישור בין צדדים".
- [ ] דיווח נשמר עם reason + target + reporter לניתוח מאוחר.
