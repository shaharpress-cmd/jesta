# מדיניות דיווח וחסימה — MVP (תמצית)

מבוסס על [00-policy-approved.md](./00-policy-approved.md) + [02-reports-queue.md](./02-reports-queue.md).  
ג'סטה מתווכת בלבד · אין הבטחת "בטוח" · אין גישור ידני.

## מה מדווחים (סיבות בטופס MVP)

| id | תווית | חומרה טיפוסית |
|----|--------|----------------|
| `harassment` | הטרדה / התנהגות פוגענית | S1–S2 |
| `threats` | איומים / אלימות | S3–S4 |
| `spam` | ספאם / הצפות | S1 |
| `scam` | חשד להונאה / בקשת כסף | S2–S3 |
| `impersonation` | התחזות | S2–S3 |
| `inappropriate` | תוכן לא הולם | S1–S2 |
| `fake_profile` | פרופיל מזויף / מטעה | S1–S2 |
| `other` | אחר (+ טקסט קצר) | לפי תוכן |

**לא ב-MVP:** `no_show_abuse` (ביטולים / "לא הגיע") — לא מזמינים גישור.

**חסימה (Block):** מיידית בין שני משתמשים; לא דורשת תור. אין ביטול חסימה ע״י המשתמש ב-MVP.

## מה קורה אחרי דיווח

1. אישור למדווח: "קיבלנו, נבדוק" — **בלי** SLA למשתמש ובלי הבטחת תוצאה.
2. אוטומציה לפי חומרה (S0–S2).
3. **3 מדווחים ייחודיים / 24 שע׳** על אותו משתמש → **הגבלה זמנית 72 שע׳** + תור.
4. S3–S4 → הסלמה לשחר.

## יעדי תגובה פנימיים (לא למשתמש)

| עדיפות | מתי | יעד פנימי |
|--------|-----|----------|
| P0 | S4 / איום מפורש | אותו יום עבודה |
| P1 | S3 / סף 3 דיווחים | תוך יום עבודה |
| P2 | S2 | 2–3 ימי עבודה |
| P3 | S1 | אוטומטי / תור שבועי |
| P4 | S0 | סגירה אוטומטית |

## מתי אסקלציה לשחר

✅ איומים, סחיטה, חשד לפשע · התחזות עם נזק · דפוס הונאה · חסימה קבועה · שינוי מדיניות · כל S4  
❌ "לא הגיע" · ויכוח על עזרה · ספאם בודד שטופל אוטומטית

**לא:** הפניה למשטרה בהודעות ב-MVP (עד עו״ד).
